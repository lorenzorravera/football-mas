# Session datasets — multi-step memory experiment (Phase C)

Each `*.json` here is **one scripted conversation** (ordered turns in a single session).
The [session_runner](../session_runner.py) plays each through four arms
(`mas_memory`, `mas_no_memory`, `single_llm_stateless`, `single_llm_history`) and
[session_report](../session_report.py) reports per-session paired deltas + effect sizes.

These are **not** the old independent-golden-query experiments — they test
**within-session carry-over**, which had not been run before.

## File schema

```json
{
  "session_id": "correction_referee_01",     // unique; also used to namespace memory
  "sub_experiment": "correction",            // correction | cache | conversation
  "variant": "no_control",                   // data_analyst variant for MAS arms
  "description": "what this session probes",
  "turns": [
    {
      "turn_index": 0,
      "query": "natural-language user turn",
      "role": "trigger",                      // trigger | beneficiary | filler
      "ground_truth_sql": "SELECT ... ;"      // executed read-only to score the answer
    }
  ]
}
```

### Roles
- **trigger** — the turn that seeds memory (a failure for `correction`, the first ask for
  `cache`, the topic-setter for `conversation`). Excluded from the primary metric.
- **beneficiary** — a later turn that *should* benefit from what the trigger stored.
  **This is what the primary metric scores.**
- **filler** — unrelated turn; used by the **guard** metric (must not regress).

### Ground truth
`ground_truth_sql` is run read-only at scoring time; the answer is scored on whether the
expected key numbers/names appear. PL-scope every query
(`JOIN competitions ... WHERE league_code='ENG-PL'`), season format `'YYYY-YYYY'`.
> ✅ **All 44 `ground_truth_sql` across the current 19 sessions have been validated against
> the live DB (2026-06-30): each returns a non-empty, non-null result.** The scaled set was
> generated by [eval/gen_sessions.py](../gen_sessions.py), which renders SQL from validated
> pitfall templates and refuses to emit any session whose ground truth comes back empty.
> Re-run that script to regenerate or extend; it re-validates on every run.

## The three sub-experiments

**correction (headline)** — seeded from the three known failure patterns in
[phase23_seeded.py](../../phase23_seeded.py): referee-name matching, team-season
aggregation, player-name joins. The trigger asks a question that hits the pattern (and
tends to fail); the beneficiary asks a *semantically similar* question on the same
pattern. Memory fires on similarity (correction threshold 0.75), so trigger and
beneficiary must be about the same kind of thing.

**cache** — the beneficiary is a near-repeat of the trigger (sql_cache threshold 0.88).
Accuracy should be unchanged; the win is latency/token savings (read from
`trajectory_log`, `experiment='session_eval'`, joined on `query_id`).

**conversation** — the beneficiary is a follow-up that *refers back* ("their away form?",
"is he injured?"). The win is reference/entity resolution from prior-turn context, not
similarity.

## Scaling to the paper
**Current suite: n = 19** (9 correction / 5 cache / 5 conversation), up from the 4 starters.
Generated + validated by [eval/gen_sessions.py](../gen_sessions.py). The runner globs this
directory, so add more `*.json` files (or `--glob 'correction_*.json'` to run one family).
Teams, seasons, referees, and players are varied across sessions so retrieval is genuinely
exercised rather than memorised.

> **Results (n=19, 2026-06-30):** `mas_memory` beats every baseline on the *correction*
> sub-experiment (beneficiary Δ = +0.22 vs no_memory, +0.28 vs stateless, +0.33 vs
> full-history) and on *conversation* (+0.65 vs stateless); *cache* is 0.00 by design (latency
> win, not accuracy). Full write-up:
> [../results/SESSION_RESULTS.md](../results/SESSION_RESULTS.md). Two mechanism details made it
> work: (1) the harness **oracle-seeds** a general correction lesson after a ground-truth-judged
> failed trigger, because the rule-based `eval_agent` can't detect wrong-but-self-consistent SQL
> (see `session_runner._seed_correction`); (2) a **SQL-cache entity guard**
> (`vector_store_pg._cache_consistency_ok`) — the first run was inverted by the semantic cache
> reusing entity-mismatched SQL until that was fixed. Run:
> `python eval/session_runner.py` (LLM cost) + `python eval/session_report.py`
> (or `session_report_partial.py` mid-run).
